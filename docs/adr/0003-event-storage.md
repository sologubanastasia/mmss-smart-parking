# ADR-0003. Подійне зберігання відео та розділення сховищ

## Статус

Прийнято, 2026-09-27.

## Контекст

Постійний запис 50 потоків по 3 Мбіт/с створює приблизно 1,62 ТБ даних на добу. Службі безпеки потрібні фрагменти інцидентів, але для статистики зайнятості достатньо структурованих подій. Номерні знаки та відео потребують обмежених строків зберігання й аудиту доступу. Потрібно збалансувати розслідування інцидентів, вартість сховища та мінімізацію персональних даних.

## Варіанти

1. **Постійно зберігати все відео.** Максимальна повнота, але надмірні витрати й ризик накопичення персональних даних.
2. **Зберігати лише метадані.** Мінімальні витрати та ризик, але неможливо візуально перевірити спірну подію.
3. **Подійне зберігання.** Постійно зберігати структуровані події, а відео — у вигляді обмежених фрагментів навколо в'їзду, виїзду, конфлікту або інциденту.

## Рішення

Обрано подійне зберігання з розділеними сховищами. Metadata DB містить стани, сесії, часові мітки, посилання на медіа та псевдонімізовані ідентифікатори. Event Media Storage містить зашифровані фрагменти відео й кадри номерів. Local Video Buffer на edge-вузлі зберігає сире кільцеве відео до 12 год на окремому зашифрованому накопичувачі місткістю 2 ТБ. Подійні фрагменти зберігаються 30 діб у Event Media Storage з корисною місткістю щонайменше 8 ТБ на одну парковку. Після завершення строку фрагменти видаляються, а довготривала статистика не містить зображень і відкритих номерів.

## Наслідки

### Позитивні

- довготривалий обсяг відеосховища зменшується приблизно вдесятеро за 10% подійного часу;
- метадані оптимізовані для пошуку та звітів;
- чутливі медіадані мають короткий контрольований життєвий цикл;
- відмова об'єктного сховища не блокує визначення стану місць.

### Негативні

- подія, яку алгоритм не виявив, може не мати довготривалого відеофрагмента;
- потрібно синхронізувати транзакцію метаданих із завантаженням медіа;
- політика видалення й юридичне утримання даних ускладнюють життєвий цикл;
- оператор не може довільно переглядати повне відео, старше за 12 год;
- 12-годинний буфер обмежує час реагування на невиявлений алгоритмом інцидент.

### Перевірка

Рішення перевіряється тестом пошуку FR-10, аудитом строків зберігання та звіркою подій із файлами Event Media Storage.
